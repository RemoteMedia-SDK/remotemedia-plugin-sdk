## Why
The runtime cancels a call by dropping its future (barge-in, latest-input-wins supersession, a cancelled RPC, a closed session). That stops only the work that lives inside the future. A node that generates on another thread, in a worker process, on a GPU stream or behind a remote API keeps producing a reply nobody reads, and the next call queues behind it. The Gemma assistant did exactly this outside room mode until `remotemedia-sdk-base@bbf4ee8`: five aborted calls in a row pushed time-to-first-text from 5.3 s to over 9 s. Nothing in the node contract required it to stop, so the defect was found by measurement, one node at a time.

Cancellation support today is per node and optional. `CancelGate` is reachable only by downcasting the host context, and `cancel_force` is never called outside a test. `InterruptableBackend` has no implementations and the runtime never calls it. Only native workers get `is_cancelled()`. Python nodes each hand-roll a `request_barge_in` latch. Many generators have no latch at all, and the `python_plugin_export`, `python-source-plugin`, mapped and in-process Python modes forward only `shutdown`, so even the nodes that have one never hear a barge in those modes. Of roughly 50 generating nodes in the workspace, about half stop only when a write to a dropped consumer fails, and several (`KokoroTtsNode` in litert, `TestToneTtsNode`, the candle LLMs) run each job to its end.

## What Changes
- Add one per-call cancellation signal, `CancelToken`, to the shared traits. Every call context carries one; the host fires it, with a `Cancellation`, before it drops a cancelled call. It is usable from async code, blocking threads and FFI callbacks.
- Make every cancellation say what happens to data. A `Cancellation` carries a reason and a `Disposition`: whether the node keeps or rolls back what it generated before the cancel (`partial_output`), and whether input already received or queued is kept for the next call or dropped (`pending_input`). An *interrupt* (the default for barge-in and supersession) retains both, so a VAD-triggered barge stops generation while the user's audio keeps flowing into the next inference. An *abort* (retracted speculation, caller cancel, session close) discards both. The canceller, the manifest and the node can each set it, in that order of precedence.
- Add a typed node role. Every node that generates text, audio, video or images (including avatar, lip-sync and motion renderers) is a generator and MUST implement `Cancellable`, which states how it stops (`CancelStrategy`) and may stop out-of-band work (`on_cancel`). Generator marker traits (`TextGenerator`, `AudioGenerator`, `VideoGenerator`, `ImageGenerator`) have `Cancellable` as a supertrait, and the generator registration and export paths accept only types that implement them, so a missing implementation is a compile error.
- Give Python generators the same contract, typed and enforced as early as Python allows. `remotemedia.core.cancel` mirrors the Rust types (generated from one schema, with a parity test). `GeneratorNode` and `TextGenerator`/`AudioGenerator`/`VideoGenerator`/`ImageGenerator` work with both `MultiprocessNode` and `InProcessNode`. A generator missing `cancel` fails mypy in CI, fails at import (`__init_subclass__`, `@register_node`), and cannot be instantiated (`abc`). The legacy `Node` base cannot host a generator.
- Declare the role and strategy in `NodeSchema` and the factory `describe()` JSON (`generates`, `cancel`). The host refuses to register a node that declares `generates` without `cancel`, and pipeline validation refuses to admit one. This covers loadable plugins and Python nodes, which the Rust type check cannot see.
- Fire the token, with its reason and disposition, across every execution boundary: a new defaulted `FfiNode::cancel_call` entry that the host calls before it drops a plugin call (with a drop guard as fallback); native workers through their existing cancel message; every Python mode, including `python_plugin_export` and `python-source-plugin`, through one per-call cancel frame to a `GeneratorNode` base class whose `cancel()` is abstract.
- The router honours `pending_input`: an interrupt no longer discards the inputs queued for the node.
- Add a reusable conformance check, `assert_generator_cancels`, that every generator must pass: after a cancel no further output arrives within a grace period, `on_cancel`/the token is observed, the next call's time to first output is not delayed by the abandoned one, and each disposition is honoured.
- Speech-to-text and voice conversion are not generators.
- Classify and migrate every existing generating node (inventory in `tasks.md`), and fold `InterruptableBackend` into `Cancellable`.
- **BREAKING (authoring API)**: generator nodes must implement `Cancellable` to compile against the new plugin-sdk minor version, and Python generators must derive from `GeneratorNode` and implement `cancel()` to import; `InterruptableBackend` and `StatefulConversationBackend::finalize_turn` are deprecated in favor of `Cancellable` and dispositions.
- **BREAKING (ABI)**: `ABI_VERSION` moves to 0.11 for `FfiNode::cancel_call`; plugins must be rebuilt to receive the cancel reason and disposition.
- **BEHAVIOR**: once a generator declares its role, a barge-in retains its queued input instead of discarding it, unless the canceller, manifest or node chooses `Discard`.

## Impact
- Plugin SDK (`remotemedia-plugin-sdk`, owner of this change): `crates/traits` (`CancelToken`, `Cancellable`, generator traits, `NodeSchema`/`NodeDescription` fields, `NodeRuntimeContextRead::cancel_token`), `crates/modality` (generator traits per modality), `crates/core-derive` (`#[node(generates = ...)]`), `crates/plugin-sdk` (ABI adapter drop guard, native-worker bridge, Python worker cancel frames, conformance helper), docs `LOADABLE_NODE_ABI.md`.
- Host (`remotemedia-sdk-base`): fire the token at every cancel site in `src/transport/session_router.rs` and `cancel_gate.rs`, the registry/validation check in `src/nodes/` and `src/validation/`, the loadable adapter in `src/loadable/`, Python multiprocess bridge in `src/python/`, and migration of built-in and example generator nodes (`src/nodes/`, `examples/litert-nodes/`).
- SDK (`remotemedia-sdk`): Python contract (`clients/python/remotemedia/core/cancel.py`, `GeneratorNode`, `@register_node`, the worker runner's cancel frame and discovery frame, mypy in CI), the Python conformance twin, Python generator migration, Python plugin examples, and the in-process cancel/barge-in suite.
- Host Python registration (`remotemedia-sdk-base/crates/python-nodes`): `PythonNodeConfig` declarations and the discovery cross-check.
- Barge producers (VAD gates, `ConversationCoordinatorNode`, `HostedTurnNode`, scaling `InterruptNode`) set an explicit disposition.
- Separate plugins (`candle-nodes` and other generator plugins): rebuild against ABI 0.11 and implement `Cancellable`.
- Related changes: `add-session-rpc` (call cancellation of RPC), SDK `add-ai-sdk-voice-library` task 8.4 (the Gemma fix this generalises).
